# Readiness review

Review only supplied evidence. This public checklist uses no numeric scoring or automatic approval threshold. A PM decides readiness after resolving blockers.

| Check | Question |
| --- | --- |
| Purpose | Is the requested outcome and problem clear? |
| Scope | Can the reader distinguish included work from exclusions? |
| Actors | Are the affected roles and relevant access rules defined? |
| Criteria | Can each required outcome be checked? |
| Dependencies | Are blocking decisions and dependencies identified? |
| Evidence | Are behavior and values supported, with unknowns marked TBD? |
| Clarity | Can the title and description stand alone? |

For each check, report supported, missing or not applicable, with a short reason. Report blocking gaps before stylistic suggestions. Do not call a ticket ready while a blocking product decision is unresolved.
