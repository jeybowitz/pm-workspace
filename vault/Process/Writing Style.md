# Writing Style

Editable defaults. Product vocabulary and language belong in Workspace Config.md.

## Plain-language test

Use short sentences and familiar words. State concrete behavior, decisions and evidence. Remove lines that add no information.

## Rules for every artifact

- Use documented product vocabulary; preserve distinctions between entities.
- Use TBD for unknown values and cite sources for verified claims.
- Describe the intended result; keep editing history out of the body.
- Write observable requirements. Leave layout and implementation to their owners unless explicitly constrained.
- Use links the recipient can open. Local paths belong only in local context.
- Attribute stakeholder statements to roles. Keep personal details in private sources only when necessary.
- Put technical details and provenance in AI Context for Discovery documents.
- Use the configured artifact language; preserve actual UI labels when quoting them.
- Use simple hyphens in prose.

## Words to avoid

| Avoid | Prefer |
| --- | --- |
| handles / processes without an object | State exactly what changes |
| lays the groundwork | Name the delivered behavior |
| undefined product terminology | Use your glossary |

Extend this table for your team. Historical vocabulary examples are not universal rules.
